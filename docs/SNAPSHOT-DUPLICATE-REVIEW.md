# 本地快照重复记忆审阅

在个人管理台选择“核验／对照本地快照”，明确选择文件并完成整体核验后，点击“审阅快照中的同文记录”。选择左侧或右侧已核验文件，勾选全部项目／全部状态扫描同意，再点击“扫描同文记录”。打开面板本身不扫描。

本模块复用离线 `duplicates` 的唯一算法。原文必须完全相同，不规范化空格、大小写、换行或 Unicode，不把哈希碰撞当成同文。候选、已启用、已归档、不同项目／权限／来源类型均纳入整份文件的扫描。浏览器和 CLI 通过同一规范合同验证文件；原 Node 模块仅保留向共同实现的重导出。

## 分组、分页与对照

重复组每页10组，组内成员每页20条，最多覆盖既有合同的1000条记录，不截断扫描后再报告。默认仅显示数量、内容指纹和成员元数据；原文、来源说明、引文均不自动显示。每组可以打开成员列表，跨页将不同的两条记录选择为 A、B。另行勾选完整正文显示同意后，点击“显示 A／B 完整记录”，才显示两条本地快照记录的完整字段。内容通过纯文本节点显示，不解释HTML或脚本。

选择A/B、翻成员页会清除已显示正文及正文同意，但保留该组的A/B编号以支持跨页选择。换组／翻组页会清除成员、选择和正文。换文件、撤回扫描同意、重新核验、关闭核验窗口、切换视图、锁定管理台或进入已有快照浏览／差异对照，会使旧审阅失效。未保存的独立编辑草稿不被覆盖。

扫描与单个大组的成员投影都会周期性让出事件循环，并在恢复时复核授权。取消不会交付部分统计；迟到的旧失败也不会清掉新的成功结果。只有完成扫描的合法零组结果才能解释为这份文件没有同文组；未读取和失败不等于零组。

## 权限与限制

管理台本身仍需先按既有规则登录。审阅仅处理已经明确选入并核验的本地快照；所选文件、关键字或正文不会进入管理台数据接口。加载页面及共享脚本是静态代码请求，不应误称管理台启动全过程零网络。审阅操作不查询当前数据库、不写浏览器存储、不下载或上传文件、不调用模型、不自动删除、合并、归档或选择保留者。

快照核验只证明内部一致，不验证作者、所有者身份、数字签名、文件完整来源或当前数据库状态。相同原文不意味着项目、权限、版本、来源、引用或生命周期可互换。`additional_occurrences` 是重复出现次数，不是可删除数量。引用未做语义等价比较；即使所比较的元数据字段相同也不是安全合并批准。记录ID和指纹仍属于私有元数据；清除UI引用不是安全擦除内存承诺。

## 测试入口

```bash
node --test test/personal-snapshot-duplicates-ui.test.mjs test/personal-snapshot-duplicates-shared.test.mjs
node test/personal-snapshot-duplicates-browser.mjs
```

第一组执行生产UI代码的合成DOM测试、真实共享算法和固定HTTP资源检查。第二条命令以生产HTTP/CSP和真实Chromium读取本地合成快照；数据库适配器仅允许管理台启动和登录初始列表，审阅阶段不应有数据库请求。安装Python Playwright及Chromium由独立CI工作流完成，见 `.github/workflows/snapshot-duplicate-review.yml`。

另有 `python test/personal-snapshot-duplicates-browser.py --offline` 测试模式：生产HTML、CSS和全部7个脚本在真实Chromium离线上下文加载，仅摘要计算由Python SHA-256桥接。这个模式不是在线HTTP/CSP、原生WebCrypto或真实PostgreSQL验收。实际结果和未完成门槛请查看相应提交及 `docs/reviews/snapshot-duplicate-review/`，不能用测试脚本存在代替通过。
