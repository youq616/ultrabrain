# 人工双记录核对

管理台的“人工双记录核对”入口允许用户明确填写两条不同记忆的完整小写 UUID，点击“读取／刷新这两条记录”后，左右显示各自的正文、状态、版本、类型、项目、可见性、所有权、重要性、可信度估计、来源说明、内容指纹与已有引文。打开视图或修改编号不查询服务器。

这是人工选择和观察，不自动寻找相似项，不判断陈述是否矛盾，不推荐保留哪条，不运行模型，也不保存成对裁决。既有同记录编辑版本对照仍只处理并发版本变化；离线快照同文分组也不是本入口的选择来源。

## 读取与来源边界

每次最多两条顺序 `memory_read`，只发送明确填写的 ID。沿用已有来源／主体认证、完整记录校验和内容 SHA-256 检查，不新增 API、MCP 权限或数据库字段。两个 ID 必须不同；任一读取不可用或校验失败，整对不展示，不保留第一条或上一次结果。不存在和无读取权限仍统一为 `not_found`，不能据此断言记录已删除。

两条结果是分别读取时的观察，不是事务内同一快照，也不持续刷新。读取后任一条可能变化；再次点击读取会重新取两条记录。已归档的自有条目可以核对；他人记录仅在现有共享规则允许时可见，文件片段继续由文档生命周期管理。

结构化引用复用已有 `lineageReference` 合同核验，显示的是本次记忆行携带的历史引文、生成时原文版本与 UTF-16 区间。这里不重新读取来源，不将来源有效标志或内容哈希作为事实真实性证明。若需核对实际原文，先进入单条精确读取，再使用既有“核对记忆引用来源”。引文更新只有再次读取记录才能观察；来源自身变化需另行来源核对。没有引用字段不证明他人共享记录没有来源。

所有正文、来源及引文均以纯文本节点显示，不生成 HTML、自动打开链接或下载文件。ID、项目和来源也可能属于私有内容；页面不自动脱敏，不写浏览器持久存储。面板不导出成对内容，也不承诺清除后的物理内存擦除。

## 分别操作，不制造裁决状态

“重新读取此条，再单独处理”只取对应 ID，重新进入既有单条核对入口，不把左右缓存填成编辑基准。旧按钮在选择已改变后失效。新读取失败时不能退回旧缓存继续编辑。用户明确点击原有“编辑”才填入该次读取版本；未保存草稿在双记录读取和单条跳转中保留。

保留两条可以不修改；需要修改或归档则逐条明确操作。保存依旧检查 `expected_revision`，修改后回到 candidate，启用需单独确认。共享记录和文档片段不因本入口取得编辑权。这个模块没有“可共存”“替代”或“待复核”的持久关系，也不把归档伪称成有审计记录的成对裁决。

## 撤回和失败

修改任一 ID、取消、刷新、导航、锁定、开始写入或打开其他来源／快照工作区都会清除已读结果并取消等待。每次请求前后、异步指纹检查后与后续跳转前均复核会话、来源、视图、选择和未确认写入状态。迟到结果不能恢复旧面板；取消不能撤回已经到达服务器的只读请求。未确认写入仍须先处理原事件，不能借助此入口绕过。
