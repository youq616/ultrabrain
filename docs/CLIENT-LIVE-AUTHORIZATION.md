# 长连接 MCP：逐次授权、取消与不可变请求

本阶段修复的是已安装 Node 客户端的 `mcp --profile PATH` 长连接转发器，不是新增服务端权限、企业功能、模型或自动事实确认。

## 用户可观察的变化

代理启动时绑定已经读取的可信 profile。每次读取工具目录、校验身份、发送工具调用及返回结果时，都重新读取并校验该 profile。权限、来源、端点、实例 pin 等解析配置一旦被观察到变化，或者文件缺失、损坏、不再可信，当前连接永久拒绝后续操作，返回安全的 `client_authorization_revoked`。修复/恢复文件不会悄悄复活旧连接；必须由用户重新启动客户端，并重新建立可信身份。工具目录查询失败时返回协议错误，不继续展示缓存的写工具，也不暴露原始文件异常。

普通 JSON 空白格式变化不算权限变化。守卫针对读取到的完整解析配置，不是文件系统监视器，不能保证检测到两个检查之间发生又撤回的瞬时修改，也不声称能隔离恶意同 UID 代码。已经运行的远端工作不会因为本地配置变更被自动撤销。

程序化 `connectClient(input,{signal,authorize})` 可提供同步连接级授权断言；没有回调时仍使用显式传入的静态可信配置。回调返回 false 或抛错即拒绝；Promise 被拒绝并处理其 rejection，不会把异步对象当成同意。连接级断言保护所有该连接的工具请求和目录分页；它不替代 capture/task/document 原有的单次授权条件。程序化调用没有 profile 文件路径时，不会自行猜测或扫描文件。

## 发送与返回边界

`callAllowed` 在第一次异步身份检查之前复制完整工具请求，包括嵌套 memories、consent 和稳定 event_id。调用方在等待期间修改原对象，不再改变最后实际发送的字节。原有只读工具列表、写入开关和采集 consent 校验保留；文档导入仍执行同一个原始文件合同。服务端推导 source/principal 的身份边界和现有各工具 project 语义未更改，不把一个 project 选项宣传成整个 MCP 工具面的新 ACL。

下游请求的取消信号与连接取消信号组合，覆盖身份检查和最终工具调用；工具目录的信号也覆盖当前页。每次等待后、发送前及返回后检查取消和授权。目录只返回本连接初始工具集合与当前允许目录的交集，不在长连接内采用新增工具。

若读取已经到达服务器但本地授权随后撤销，结果正文不会再交给调用方。若写入已经提交，撤销不能撤回数据库提交或费用；代理保守地返回 `delivery:unconfirmed`，不自动再次执行写操作。重新建立可信连接后，调用者可以用同一 event_id 与同一内容检查/重放；不得换新事件 ID 来“重试”。错误可能发生在本地写入前，因此 unconfirmed 也不代表服务器一定收到过写请求。

## 本阶段验证范围

单元回归使用未改写的客户端 runtime 加明确的模拟 SDK；这只证明 runtime 逻辑边界。专门的 `test/client-proxy-lifecycle-integration.mjs` 通过实际安装的客户端 tgz、官方 MCP SDK、原生 MCP 与托管 PostgreSQL执行候选提交→明确确认→召回→纠错回候选→重新确认→归档，并验证旧 revision 拒绝、归档离开当前上下文、授权撤回和已提交事件重放不重复入库。

该集成另使用仅在测试进程中加载的受控暂停，分别在真实身份响应后、真实上下文响应后、真实 capture 已提交后撤销 profile。暂停信号仅含固定标记，不包含原文或凭据。受控脚本代表显式用户操作，不是运行用户的 Codex/Claude/OpenCode 模型，不证明语义质量或生产主机已部署。实际 CI 与独立审查结论按完整 SHA 记录在统一验收 PR。

取消语义参照 MCP 2025-06-18 Cancellation：通知可能晚于请求完成，不能假设可以撤销已完成工作。本阶段保持仓库锁定的 SDK 1.29.0，不借此更新供应链。
