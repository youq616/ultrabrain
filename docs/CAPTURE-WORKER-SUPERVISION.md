# 采集并发验收：进程生命周期与有界报告

本模块基于 PR47 的完整提交 `1c696a97b4d5f15882a02e8fa67b75d86aa32bfa`。
它修复的是 **合成数据验收工具**，不是用户客户端的锁算法或 Windows 文件身份逻辑。
`src/`、客户端安装包、数据库迁移、上游锁、现有服务器、n8n 与 qbrain 均不改动。

## 解决的问题

原入队检查器在子进程启动失败时退回总括错误，丢失该轮逐进程结果；当一个进程失败时，其他进程的任意 JSON 字段可能被原样带入报告。两项回归在精确旧基线上均失败。现在失败轮、已完成轮和最多八份固定字段报告保留，路径、正文、原始错误信息和任意附加字段不透传。

上轮 Ubuntu/Node22 CI 工件 `11049682543` 还记录了“early-exit 预期 ready，实际 enqueue”。原因在故障夹具：异步 stdout 回调尚未退出，真实 worker 已继续导入并发送 ready。夹具现在以顶层 await 阻止真实 worker 导入，不通过扩大允许阶段或删断言处理。

## 完整生命周期

`test/helpers/capture-worker-batch.mjs` 是两个固定检查脚本共用的内部监管器，不是可执行任意命令的公开 API。父程序仍启动八个真实 Node 进程，子进程与生产队列操作本身不变。

只有预期阶段的单字段 `ready:true`、`staged:true` 消息可以推进屏障。重复、提前或附加字段消息失败。派发前验证全部进程状态并准备全部消息，再逐个发送；IPC 回调失败不重试，send 返回 false 仅表示背压，不等同发送失败。缺失发送回调确认不能判成功。

ready、staged、exit、stdout 或 kill 请求都不是最终成功证据。必须有完整协议、成功发送回调、exit=0、无信号、close 已到达、无监管错误、无 stderr、合法最终报告，才允许该 worker 通过。父脚本之后仍检查真实队列记录、正文、尝试次数与 CAS 胜者数量，不以子进程自报成功替代队列核验。

stdout 按字节最多保留 4096 字节，完成后严格 UTF-8 解码，跨块多字节字符不会被提前替换。stderr 只记存在标记，不保留内容；锁、日志及嵌套本地读取诊断沿用固定枚举投影。序列化报告不是 WeakMap 认证错误、服务器回执或真实性证明。

工作期限默认 15 秒，派发与 close 观察也检查单调时钟；事件循环延迟不能授权过期后的新派发。失败停止本批自己创建的进程，已断开 IPC 的退出过程最多留 50 毫秒排空错误报告，每个未退出子进程最多请求一次 SIGKILL，之后最多等 2 秒 close。没有确认 close 时报告 `workers_closed:false / cleanup_skipped:true`，保留临时目录，不能把 kill 请求当作进程已结束。检查器不承诺被阻塞系统调用或事件循环的硬实时截止，也不是恶意子进程/后代进程的隔离沙箱。

临时根目录与 workspace 的创建也处于受保护的 setup 阶段。准备失败返回失败轮；已经成功的先前轮不会消失。只有确认子进程关闭后，才清理该检查器生成的合成临时目录。真实用户队列、已有锁和用户配置从不被选择、删除或修复。
