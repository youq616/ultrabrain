# 自有个人记忆快照导出

管理台的「导出我的记忆快照」与原「导出当前页」是两个独立入口。快照导出在一个只读、可重复读事务中读取当前所有者的全部记忆状态及全部项目；不依赖当前搜索条件，不拼接多次实时分页，不调用模型，不新增记忆或任务。

## 使用和范围

在个人管理台连接后，点击「导出我的记忆快照」，阅读范围说明并勾选独立同意，再点击「核对并下载记忆快照」。文件固定命名为 ultrabrain-owned-memories.json，包含当前身份自己拥有的候选、启用、归档记录，以及作为记忆记录存在的原文和文档片段。它不包含其他所有者共享过来的记录，也不读取浏览器草稿。导出后同意会清除，不自动重试或重复下载。

**这不是完整数据库备份。** 不主动读取或导出原始文档文件字节、任务/事件历史、Agent 注册表、服务配置及凭据文件或外部对象。若已保存的记忆正文或引用本身含有秘密，本模块会原样包含，不进行自动识别或脱敏。本模块也没有快照导入、数据库覆盖或跨身份恢复入口。派生记录的引用保留为数据，不能凭此恢复历史版本或证明其内容真实；完整恢复仍使用项目既有恢复套件。JSON 是私有明文，需由用户保护下载目录及副本。

## 一致性、数量和字节限制

服务端仅复用现有 PersonalMemoryStore 的公共记忆投影及 rowView；来源/所有者来自服务端上下文，不接受调用方选择 actor_key/source_id。导出始终限定 m.source_id 与 m.actor_key，同时包含全部生命周期状态。构造后发生的权限撤回或身份变化会被再次检查，不返回旧身份结果。

第一个查询之前设置 `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ, READ ONLY`，然后设置事务内5秒语句超时。预检与正文查询共享同一数据库快照。预检最多考察1001条并返回数量和序列化大小，不把超限正文传到客户端；最终再次检查完整结果的字节数。最多1000条，完整紧凑JSON结果最大8 MiB，任何上限超出均整体失败，不截断、丢行或提供 partial success。需要更大范围时使用既有数据库备份工具，而不是把几次导出拼成所谓一致快照。

一致性对应数据库快照，不是查询结束时的最新状态，也不是对查询后权限变化的持续授权。snapshot_at 是第一次数据库查询的时间标记，不是全局同步时间证明。PostgreSQL 的可重复读语义见官方文档：https://www.postgresql.org/docs/18/transaction-iso.html#XACT-REPEATABLE-READ 。只读事务不等于数据库引擎完全不写任何磁盘页面，本模块承诺的是不修改应用记录。

## 单一导出合同

src/personal-snapshot-contract.mjs 是服务端与浏览器共同使用的纯 JavaScript 合同。固定格式 ultrabrain-owned-memories-v1，范围 owned-memories-all-states，包含 source_id、请求随机 UUID、时间、完整/只读标志、准确条数、明确排除项、按ID排序的 memories 与 memories_sha256。complete 只表示此定义范围内的当前所有者记忆完整，不表示全库完整。

摘要覆盖 `JSON.stringify(memories)` 的 UTF-8 字节，且每条内容另行核对既有 content_hash；检查重复/乱序ID、非自有行、遗漏字段、额外内部字段、非法日期及错误计数。导出是数据，不将未知文本当作指令、HTML或模型可信事实；不在导出时修改置信度、合并或激活记录。哈希仅证明收到的数据内部一致，不是签名、来源认证、磁盘持久化证明，也无法证明恶意服务器没有隐瞒其他行。

唯一新增控制台操作是 memory_snapshot，输入仅为 `{request_id: "完整小写UUID", consent: true}`。它是认证后的只读操作，不计入写入/事件机制。现有 MCP 工具目录和客户端接口不变；没有新通用查询或文件读取端点。/snapshot-contract.mjs 是固定的无秘密静态代码路径。

## 取消及错误

浏览器在模块加载后、发送前、收到结果后、每次异步哈希后及下载前复核原会话、来源、导航、明确同意及未确认写入状态。撤回导出同意、取消、刷新、导航、锁定或开始写入使旧导出失效；即使网络取消没有及时生效，迟到结果也不会触发下载。已发送的只读查询无法撤回，取消不删除任何服务器记录。

动态加载、网络、身份、结构、指纹、容量或存储错误都不会产生部分文件、写入重试事件或自动备用下载。导出过程不清空无关草稿。服务端限制返回结果的大小，并非对恶意网络响应的流式内存硬上限。

## 验证入口

`node --test test/personal-snapshot.test.mjs test/personal-snapshot-browser.test.mjs` 测试实际服务方法、共享合同和页面处理函数；数据库/DOM/HTTP是合成替身。真正 PostgreSQL/Chromium 验收位于 test/personal-snapshot-integration.mjs 与 test/personal-snapshot-browser.py，由现有个人浏览器 CI 追加执行。

真实数据库测试用另一个事务在预检与正文读取之间更新并插入，要求同一次导出仍为旧的完整视图，下一次导出才反映新提交；验证其他所有者隔离、数量/字节整体拒绝、实际认证路由和浏览器动态模块加载。浏览器测试仅导出一次，其他故障/取消不下载，前后六张应用表指纹不变。所有数据均明确合成；没有外部模型或用户服务调用。阶段最终验收以精确提交的CI及独立审查记录为准。
