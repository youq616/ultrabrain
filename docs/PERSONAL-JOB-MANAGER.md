# 整理任务管理模块

这个模块将原有整理任务接口接入一个可核对的操作流程：按状态分页或完整 ID 查任务，明确追踪原文和生成候选，检查尝试次数与租约信息，确认后取消未完成任务，并处理不可靠取消回执。不是新的一套队列，也不会自动运行模型。

## 管理台使用

打开「整理任务」读取当前本机所有者的元数据。状态可选全部、等待整理、处理中、处理失败、已整理、已取消或来源失效；每页最多20条。填写完整小写 UUID 后点击「读取任务」，按 ID 精确查询，不受列表状态筛选影响。输入 ID 本身不会发请求。不存在或不可见的 ID 返回 not_found，不显示缓存内容，也不把故障伪装成空任务库。

卡片展示任务 ID、排队时的原文 ID/版本、状态、尝试次数、错误代码、创建与更新时间，以及适用的租约时间。租约是否过期、是否能恢复以服务器判断为准，页面时钟和 retryable 都不授予执行权限。已完成任务展示生成候选的数量；零候选也是合法结果，不代表模型确认了任何事实。

点击「核对原文记录」或「核对候选 #N」才调用现有精确记忆读取。实际读取的是当前可见记录，可能已经修改或归档；任务里记录的是历史结果。读取不会覆盖独立编辑草稿，启用候选仍需原有明确审核。重复提示不触发自动合并或覆盖。任务页导出仅包含当前有限元数据页，不包含原文/候选正文或页面令牌，不是完整备份。

「取消读取／清除结果」仅清空本地页面，不取消服务器任务或删除原文。切换页面、刷新、修改筛选、修改 ID、锁定均使旧读取结果失效；即使取消信号未被底层及时处理，旧响应仍不能恢复旧卡片。卡片上的读取、运行和取消在点击及确认提示之后都复核会话、来源、视图版本、选中条件与未确认提交状态。

## 取消和模型运行边界

未完成任务可明确「取消整理，保留原文」。取消成功将任务置为 stale，并使用既有租约隔离防止旧处理结果写回。取消不删除原文，不撤销已发出的外部请求或已产生的费用；已经 completed 的任务不能用此入口取消。

浏览器核对取消回执中的任务 ID、stale 状态及适用的可选来源，拒绝 dry-run 或不匹配回执。未知交付保留原任务请求，不自动重试。用户明确重试仍使用同一 job_id；取消接口没有事件编号/replayed 回执，不应称为历史事件重放或 exactly-once。再次取消可能更新任务的取消元数据，不表示外部模型没有执行。

只有点击运行或恢复并确认后，才请求处理一个任务。最多三次尝试；失败或租约到期恢复依旧遵循服务器原有规则。未配置模型时，返回 needs_model 而不发送原文给外部模型。对不确定模型处理的重试再要求一次明确费用确认：这不是幂等事件重放，可能重复计费。本模块没有改变模型处理的业务回执合同、提供商配置、模型开关或权限。

## 服务端合同

沿用 ultra_personal_jobs，只新增可选 state；不增加工具名，也不修改 governed 白名单。规范化入口是 jobStatusQuery，状态仅接受 any、queued、processing、completed、failed、stale。limit 1–100，offset 0–1000000。精确 job_id 不接受非零 offset 或非 any 状态；UI 按 ID 模式不向服务器发送列表筛选。所有者及来源始终由认证上下文推导，不接受调用方指定 actor_key/source_id。

查询在只读事务中执行，使用事务内5秒 statement_timeout，状态使用绑定参数而非 SQL 拼接。精确读取无下一页；列表只返回合法偏移范围内的游标。分页不是一致性快照，期间并发修改可能改变窗口；查询超时或存储错误会失败而不是返回成功空页。取消和处理原有事务、锁、租约以及原文保存机制未变，没有数据库迁移。

浏览器在展示任何卡片之前核对整个结果页的来源、字段范围、ID唯一性、筛选一致性、游标、规范时间戳、次数、租约和完成回执。非法页整体不显示、不导出，不裁切候选列表假称完整。结果最多1MiB；这是对收到的结构化结果的限制，不是网络层流式内存硬上限。完整性校验不是密码学证明、模型真实性认证或代替服务端权限。

## 验证与范围

两个 Node 专项执行实际浏览器脚本配合模拟 DOM/HTTP 与模拟适配器，覆盖筛选、分页、异常数据、过时卡片、取消回执和再确认。真实 test/personal-job-manager-integration.mjs 使用一次性数据库、原生 MCP dispatch 和官方 SDK stdio；test/personal-job-manager-browser.py 运行实际 Chromium。

真实集成明确注入三个合成生成器调用，分别构造完成、失败和处理中的取消竞态。这不是三个真实提供商调用。取消竞态验证旧处理不能提交候选；浏览器阶段只允许一个目标任务被取消，全部其他任务和另外五张应用表指纹保持不变，原文 candidate/r1 保留。所有内容均合成。最终提交的运行与独立代理审查结果以 PR #20 验证记录为准，不能用旧提交绿灯代替。
