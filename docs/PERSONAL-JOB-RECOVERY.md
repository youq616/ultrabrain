# 整理执行确认与只读恢复

本模块完成整理任务的执行回执核对、未知交付保留、只读状态观察、明确结束本地追踪和再次执行前的费用确认。它不增加后台重试，不把状态查询当作原请求的回执，也不承诺外部模型只调用或计费一次。

## 执行回执

管理台每次只提交一个任务。返回对象必须匹配服务端来源，并且所有返回的任务结果必须对应所选 job_id。核对 processed 数量、至多一次本次网关尝试、结果状态及完整候选回执；完成结果与任务列表共用同一校验函数。dry-run、空对象、错误来源/任务、缺字段、矛盾计数、伪造自动启用或 truth_verified 都不会清除 pending。

兼容既有真实服务端分支：未配置模型的 needs_model（无任务结果、model_calls=0）；未获得工作（results 为空、processed=0、尝试=0）；完成/失败/来源失效；租约丢失；在模型配置或来源检查处跳过的 publicJob 结果。跳过结果可携带变更前的租约元数据，不将它伪装为当前状态查询。needs_model 本来没有 job_id 回显，只能检查来源、状态、空结果和零模型调用；不会宣称不存在的绑定证明。

对任何不可靠回执保留原输入、原 job_id 和未知交付状态。正常回执仅确认收到的本次处理结果与合同相符，不证明磁盘持久化、模型内容真实性或实际费用。模型处理没有不可变事件回执，不能用普通写入的“原事件重放”保证描述它。

## 丢回执后的完整流程

出现未知交付后，原任务面板提供「核对原任务状态（不调用模型）」。只发送原 job_id 到既有 jobs 只读接口，不发送原文，不查看候选正文，不创建任务或调用模型。来源、任务 ID、排队时原文 ID/版本和不倒退的尝试次数均须匹配；元数据页必须通过原有全页校验。查询失败、错误来源或记录不匹配时继续保留原请求，不把故障解释为未执行或没有任务。

状态观察不会自动清除 pending。已完成、失败或失效的任务，用户另行勾选说明并确认后，可「重新核对终态并结束本地追踪」。该操作再进行一次只读查询；若此时已回到处理中、会话/页面变化或同意被撤回，则不能结束。成功后只结束本地追踪，不称原请求回执已经恢复，也不撤销或证明费用。观察与后续动作不是原子快照；任务仍可能被其他获授权的操作改变，尤其失败任务可以在将来重新执行。

等待或处理中保持原请求。明确重试需要先取得有效观察，再于重试时重新查询，防止已完成的任务因为旧观察被重复请求；随后还须明确确认可能重复调用和计费。发送时使用冻结的原 JSON，不能擅自改变 retry:false 为 true。最终是否有工作、租约是否有效、是否超过三次尝试，仍由服务器判断。失败任务可在明确结束本地追踪后，从原有任务卡片发起另一次已确认的恢复请求。

「取消核对／清除状态」仅清除本地观察，不取消服务器任务，也不删除原请求。刷新、导航、会话变化会使旧观察失效；迟到的查询不能显示旧状态或解除 pending。原文、独立编辑草稿不被清空。页面关闭仍可能丢失内存追踪，可明确导出原请求；没有自动跨会话恢复。

## 边界与测试

生产变更为管理台执行/恢复行为，以及 startPersonalConsole 的可信宿主依赖注入 configureModel。默认仍使用原 configuredPersonalModel，HTTP 不接受选择配置、生成函数或模型权限。这个注入用于隔离集成测试，不能由页面或不可信输入启用。数据库、取消/处理事务与租约规则、MCP 工具名称、依赖锁、模型开关和权限均未改变。

单元用实际 app.js 配合模拟 DOM/HTTP；真实 test/personal-job-recovery-integration.mjs 通过控制台、PostgreSQL 和 Chromium 验证实际执行后损坏回执、先于服务器发送的断线、同输入重试、失败观察、无可处理工作以及取消后 lease_lost。明确注入四次合成生成器调用，零外部模型调用。数据库独立核对五条原文逐字段未变、恰好两条绑定原任务的私有候选、全部任务状态/次数/租约和其他表指纹。不是模型质量评估或用户主机部署。

所有已有跨平台、文档、任务、原生 MCP、旧管理台、n8n、恢复与历史升级检查保持。正式验收只使用最终提交自己的 CI 和独立复审，记录在 PR #20；已通过的旧提交不能认证新代码。
