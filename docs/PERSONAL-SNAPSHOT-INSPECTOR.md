# 本地快照核验与差异对照

本模块接续个人记忆快照导出，供用户检查已经明确选择的导出文件、对照两份文件及核对具体差异。它不读取当前数据库，不导入或覆盖记忆，不运行模型。使用当前管理台的“核验／对照本地快照”入口；管理台页面和静态代码仍需正常加载，所以不把它描述成独立的离线安装应用。

## 使用流程

连接本机管理台，打开核验面板，选择左侧 JSON；需要对照时再选择右侧 JSON。只选择文件不会开始读取，必须勾选本地读取同意并点击“核验所选文件”。文件内容只进入当前页面内存，不发送给服务端或浏览器持久存储。文件可能含秘密，核验不自动脱敏。

单个文件通过后展示记录数、文件自述来源、时间及文件指纹，默认不展示正文。两份文件都通过后，需要另行同意对照范围，再点击比较。结果按记忆 ID 分为仅左侧存在、仅右侧存在、字段不同和完全相同；差异每页20条，所有差异保留在结果中，不截断导出。

点击一条差异的“查看所选条目的两侧内容”才显示该条目的完整字段，以纯文本显示。可单独清除正文，翻页也会清除。不会执行文件内的 HTML/脚本，也不把所选 ID 作为读取或写入服务器的权限。

明确导出的差异清单只包含范围、时间、计数、ID、不同字段名和指纹，不含记忆正文、来源说明、派生引用或文件路径。ID和指纹仍是私有元数据，须保护下载文件。这不是恢复计划，也不触发任何导入。

## 数据合同与比较语义

复用 `personal-snapshot-contract.mjs` 的导出验证器：字段、记录顺序、状态、记录数、逐条内容和完整数组SHA-256等均必须一致。磁盘文件最多16 MiB，允许导出器生成的缩进及末尾换行；解析后的紧凑JSON仍最多8 MiB／1000条。UTF-8非法序列、重复JSON字段（包括转义后的同名字段）、超过32层嵌套、合同或指纹错误均整体拒绝，不展示半份通过的结果。两侧任一失败时不会保留另一侧作为新的完整比较结果。

原始字节先复制，再进行异步指纹核验。成功结果深度冻结，比较函数只接受同一模块实例实际核验产生的句柄。比较忽略对象键的插入顺序，但不忽略数组顺序、正文字符、状态、项目、可见性、版本、时间、来源说明及派生元数据变化。相同版本也可能因关联来源变化而有不同的派生有效性，不直接判损坏。

不同自述来源的文件拒绝对照。原格式没有导出主体标识或签名；即使来源相同、owned_by_caller为真，也不能独立验证文件来自谁或两份属于同一所有者。对照同意不是身份认证，报告固定标记 `identity_verified:false`。

“仅左侧／仅右侧存在”只是集合差异，不断言新增或删除；两个文件可能来自不同时间、导出身份、不同数据库或手工生成。左右位置不代表先后时间，时间早的文件放右侧也可比较。指纹自洽不是可信来源、事实真实性、恶意服务器完整性或磁盘持久化证明。

## 取消、授权与隐私边界

改变任一文件、撤回读取同意、清除或关闭面板，会使已有结果与进行中的读取失效。对照同意撤回时清除差异和正文；导航、刷新、写入操作、打开服务器快照导出或锁定会关闭核验并释放引用。每个异步读取／指纹边界及后续查看、翻页、导出动作，还直接检查实际会话、来源、视图版本、选中文件和同意；不只依赖DOM观察器的通知时机。

浏览器File读取已开始后未必能物理中断，但取消后的结果不能显示或下载，旧失败不能覆盖新核验。清除引用不承诺浏览器内存的安全擦除。所有检查均针对当前页面操作边界，不防御恶意同账号脚本。原任务pending和独立编辑草稿不受核验影响。原生文件读取异常只显示固定错误码，不回显本地路径或原始异常内容。

## 验证

`node --test test/personal-snapshot-inspector.test.mjs test/personal-snapshot-inspector-ui.test.mjs` 验证共享逻辑及实际页面脚本；DOM/选中文件是合成对象，不当作真实浏览器证明。新增固定静态代码路径沿用原控制台头部和路径白名单，无新数据API、模型配置或MCP工具。

`test/personal-snapshot-inspector-integration.mjs` 从一次性PostgreSQL实际导出0／23／24条合成记录，供真实Chromium选择。准备阶段明确写入，浏览器阶段必须无数据HTTP请求且六张应用表指纹不变，仅允许加载静态合同代码及一次明确报告下载。其他已有集成和跨平台套件保留，最终SHA的CI和独立复审结果记录在PR #20；没有用户主机或真实模型效果验收声明。
