# Personal 0.13：开发后单独复核

基线 `a3f1790b0e837e3c4788c19de531332e55b7a908`。新客户端实现和初步测试后，复制应用到另一个审核目录，检查配置/文件权限、工作区/会话身份、模型上下文、线程生命周期、子进程边界、打包和新宿主接口，再执行既有业务和恢复回归。**仍是同一助手执行的分阶段复核，不是第二名审查者或第三方安全认证。**不宣称逐行审计全部第三方依赖或证明无漏洞。

## 发现、复现与修复

- N01：新 Hermes 方法在取出缓存后若会话并发切换，序列化后可能继续发布旧上下文。增加最后一次受锁保护的 session/generation 检查；用移除该检查的前实现变体执行新回归，1 项按预期失败，修复后通过。不是宣称此前主线已有该 provider 漏洞。
- N02：子进程 communicate 原先在完整缓冲后才检查输出大小。改成至多 32 KiB+1 的管道读取、上下文绑定的截止线程及进程/流清理；超量输出和卡死子进程回归通过。只终止本适配器创建的直接子进程，不将其描述为跨平台完整进程树沙箱。
- N03：OpenCode 项目插件必须使用经过核对的 .js 文件后缀，不能假定 .mjs 自动发现。生成器明确限制后缀，实际 OpenCode CI 门禁检查供应商收到的模型请求而非只看程序退出码。
- N04：打包检查原先只扫描主 CLI。现在三个编译入口分别检查服务端 SQL 代码未泄入，记录文件 hash，并要求 manifest、配置工具、Python provider 都存在。

所有配置仍为先 plan，再 hash 约束下显式 apply/rollback。不放开被关闭或明确拒绝的插件，不替换 OpenClaw memory slot，不自动替换 Hermes 既有外部 provider。新原生读取默认要求真实身份 pin 与精确工作目录；OpenClaw 还需精确 Agent/session。

主 CI 增加 0.12 旧应用基线（13 条升级路径），保留真实 Chromium 与 n8n。跨系统客户端合同覆盖 Windows/Linux 新 Hook 和配置工具。新增独立 workflow 必须安装真实 OpenCode 1.18.30、实际 tgz 和固定 Hermes ABC，核对 OpenCode 本地合成供应商收到的请求里含有当前个人记忆；缺依赖不得静默降级或算通过。

## 保留边界

新 Hook 全部只读，不保存会话、不自动确认记忆。读取会把选择的记忆交给 Agent 当前模型；不可信标签不是提示注入防火墙。Hermes 两秒缓存不是零延迟撤销保证，慢首轮可能无记忆。OpenClaw session 白名单不证明会话没有其他参与者，禁止用于未获准群聊。配置的本机账号、SSH alias/TLS、模型供应商仍为信任基础。

没有新增数据库迁移或改动四个上游锁、企业工具白名单。完整个人 V1、所有自动采集、Grok 实现适配、Hermes 网关、OpenClaw 全引擎、多模态及附件/密钥协调灾备仍待完成。本轮没有修改用户设备或部署。
