## 复现和修复

原 submitPending 仅依赖 HTTP/顶层 ok，接受与操作不符的空对象、事件/来源/记忆ID/版本不符的回执，并清空 pending。成功回执还无条件 resetEditor，可能抹掉等待期间用户刚改的草稿，甚至清空独立审核操作旁的未保存草稿。

本轮新增操作级校验（登记和四类记忆写入）、严格 JSON 封套、冻结重试请求与页面会话检查，确认后仅清理仍匹配的编辑选择。其他操作不清空独立草稿。未知交付继续保留原事件；已确认后 UI 错误不允许重新提交。完整范围及服务端缺少的字段见 docs/PERSONAL-CONSOLE-RECEIPTS.md；没有虚构更新/审核的事件回显或密码学证明。

## 实现自审与本地记录

首批54项回归在原实现4通过/50失败，原始首败见 first-failure.log.gz；这是上述缺口的边界用例，不是50个独立漏洞。首轮实现48通过/6失败，6个失败是新提示文字顺序与断言不一致，已调整提示而不放宽行为断言。自审还将 job 的不成立跨表UUID唯一假设改为真正的UUID形状检查；每个内存表内批量条目仍严格唯一。

既有 consent 测试夹具以前对所有写入都返回 search 的空列表。本轮将其改成实际服务端回执形状，并将假记忆ID改为规范UUID；比较测试的一份更新回执补上真实服务端必有的 replay 标志，没有移除既有测试。新增8项自审回归覆盖模糊拒绝、正确数量的重复ID、冻结嵌套请求、重试前置失败保留旧未知交付、确认后渲染失败和非编辑操作保留草稿。

最终全量测试以 local-evidence.json 和原始退出码记录为准。一次串联 Node/Python 的外层60秒时限在 Node 完成后中断 Python；中断日志保留，不计通过，Python 随后独立运行。自审是实现助手执行，不是 separate reviewer。

## 真实集成和独立审核门槛

保留19项只读浏览器快照和11项人工纠错验证，再追加回执故障阶段：真实注册/commit/capture/update/review 返回后，只对浏览器回执做受控破坏；验证前置登记不放出正文、四种操作原事件重放和提交后新草稿保留。数据库增量要求7个事件、4条记忆、1个排队任务、0个文档，11次目标写入传输中的重放不能增加行。新草稿不得写入库。

新源码创建时 CI 和独立复审 PENDING，必须以最终提交实际结果为准，不能沿用基线绿灯。后端、文档和模型整理的逐字段回执不在本轮扩展范围；不能宣传为全工具面认证。最终独立 reviewer 未公开的执行细节如实保留未披露；主线继续不接收未验收应用。
