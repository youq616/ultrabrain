# Personal background services: implementation self-review

Scope: optional personal target, console, optional authenticated loopback MCP, explicitly authorized periodic local-owner consolidation, existing database unit compatibility, safe installation/backup and the actual user-systemd CI harness. This is the implementation assistant's separate self-check, NOT an independent reviewer. The current candidate's actual GitHub Codex outcome and CI must be recorded in its PR before merge.

Default `--personal` generates only the existing PostgreSQL unit, personal console and target. Model calls and HTTP MCP each require separate explicit options. No migration, database schema, upstream pin, MCP permission, client configuration, model setting or user deployment is modified. The old database unit bytes and legacy default composition are retained. Target stop intentionally leaves the shared database running for maintenance.

Self-review tightened reconfiguration: an inactive target does not prove a manually started worker stopped. Replacement checks every personal component, rejects ambiguous manager errors, and also requires the database stopped if its shared unit would change. This is a cooperative deployment check, not a lock against other administrators starting services afterward. Inherited EnvironmentFile values cannot accidentally override the personal process's selected ULTRABRAIN_HOME; provider/environment content is still trusted operator input, not sandboxed code.

Unit-file writes use no-follow directory descriptors, bounded regular-file reads and a cooperative flock; all conflicts are checked before changing units, old differing bytes are fsynced to a private backup before replacement, and observable file/directory swaps are refused. Writes are per-file atomic, NOT a multi-file transaction. Failure can leave partial files/backups; no automatic activation follows a write failure. Existing drop-ins, externally enabled timers and legacy units are not deleted or silently overridden. No backup contains user memory or runtime credentials unless a user separately and explicitly performs a recovery backup.
