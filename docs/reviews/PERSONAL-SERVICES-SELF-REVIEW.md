# Personal user services — implementation self-review

This document is the implementation assistant's separate self-check, not a second reviewer or security certification. AGENTS.md's independent-agent/current-SHA CI gate still applies; the PR records the actual reviewed SHA and outcome.

Scope: new plan/export/verify tool, CLI routing, generated user-systemd relationships, existing worker/console contracts, consent, literal paths, export durability and actual user-manager test isolation. No database schema, upstream lock, existing systemd unit, MCP tool allowlist or model configuration is changed by the implementation.

Plan is offline and does not install/enable/start anything. Worker generation requires both explicit flags. It cannot invent provider consent, retry failed jobs indefinitely or share records between HTTP actors. RestartPreventExitStatus=2 reflects the existing worker's needs_model exit. The target is grouping, not a readiness check. Console remains bound to loopback with existing token authentication. A stop of the target leaves the existing database service running; stopping the managed database through systemd propagates to its personal dependents. Existing direct CLI database control does not gain those dependencies.

Own checks cover plan/body digest changes, source/port/interval/absolute-path validation, percent/dollar/quote escaping without a shell, private no-follow exclusive output, all file/directory synchronization, incomplete evidence, output-directory rename, byte-exact verification, unknown/modified/linked/FIFO files, root/platform refusal, safe argument errors and actual CLI wiring. The initial test of a mocked Windows platform failed inside eager shutil.which before the platform guard; dependency resolution was moved after parsing and the Linux/ordinary-user guard. This was a test-discovered error, not a claim that the service is supported on Windows. An additional self-review hardened the Python export helper against a plan object modified after its digest had been issued, with regression coverage.

The actual systemd lifecycle test has mandatory disposable-CI, explicit write-consent, ordinary-user and exact test-home guards. It refuses any pre-existing target/service of the same name, logs no raw provider/config content and cleans only its own linked units, temporary files and initialized synthetic database service. Unit-parser fixtures are not described as database tests. Local container has no user-systemd manager; actual service results must come from that dedicated CI workflow, not invented local claims. All provider responses there are synthetic localhost fixtures, not model-quality evaluation.

Remaining limitations: no automatic deployment/cutover, no unit overwrite/update transaction, no encrypted credentials provisioning, no global filesystem sandbox, no live boot/reboot verification on the user's server, no HTTP-principal impersonation, no financial cost guarantee for already submitted model calls. A verified plan is a byte-level consistency check, not source authenticity or service readiness. User-manager environment, binaries, source and export directory remain trusted operator state.
