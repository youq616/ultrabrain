Migrations, upstream pins, native client permissions and the existing database-only backup format are unchanged.

Checked: private state is not copied without both explicit flags; callers must stop application writers; live PGDATA is not copied; native contents are bounded and read through no-follow directory descriptors; links/nonregular/hardlinked files fail; original paths do not become arbitrary executable or remote inputs; manifest checksum must be pinned separately; bytes are rechecked before SQL restore; stage is inert and exclusive; restore requires trusted origin and a new constrained database name; old configuration and credentials are never applied automatically. Files are deliberately not claimed to be encrypted.

## Follow-up adversarial self-review

Two additional failing regressions reproduced defects on the first candidate: an unreadable nested native directory was silently omitted by os.walk, and runtime activation between the preflight and manager-lock acquisition was not rechecked. The implementation now raises on traversal errors and checks execution code/upstream/runtime binding after taking the manager lock, before database creation. A durability review also added explicit dump/file-manifest and database-directory fsync before the top-level completion marker. These are implementation-assistant findings, not attributed to Codex. The corrected source requires new tests and a fresh external review before merge; the first candidate is not accepted.

The dump now also inherits a bounded RLIMIT_FSIZE (never relaxing a stricter operator limit); the previous process limit is restored on failure. This bounds the dump file during generation instead of accepting unbounded temporary writes until the final size check. A child-process regression checks inheritance and exception cleanup.
