# 二进制跨主机兼容性

新构建使用 `portable-v1` 独立目录，并向 pgvector make 传入 `OPTFLAGS=""`，不把编译主机的 `-march=native` CPU 指令要求带到其他服务器或 CI runner。既有运行目录不会被覆盖；同一上游版本切换到新构建也需要先停服务、停库，再执行 `db activate-runtime`。支持的操作系统/架构及动态库依赖仍须匹配，这不是跨 Linux 发行版或跨 CPU 架构的通用二进制承诺。

CI 的失败诊断只输出后端终止信号编号和恢复次数，不输出 SQL 或完整服务器日志。恢复状态本身不能证明根因是 CPU 指令；应结合崩溃诊断判断。
