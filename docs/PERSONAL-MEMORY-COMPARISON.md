# 保留草稿的版本冲突对照

个人管理台增加「读取当前版本对照」，用于一条正在编辑的普通自有记忆。它复用既有 `memory_read` / `PersonalMemoryStore.read`，只发送完整记忆 ID，不发送草稿、不写库、不调用模型，也不新增 MCP 工具或权限。

## 操作顺序

保存遇到明确 `revision_conflict` 后，原编辑基准和草稿保留。点击「读取当前版本对照」会展示三个纯文本区域：开始编辑时的版本、数据库本次读取版本、我的待保存草稿。正文以外，类型、项目、可见性、来源、重要性和可信度估计也展示，避免只看正文而忽略其他字段。

读取不会自动改动 `expected_revision`。只有勾选独立的对照确认、点击「采用新基准，保留草稿」并确认提示，才把这次读取的版本设为本地保存基准。草稿全部字段保持原样，包括可信度估计；它不会自动合并或保留数据库另一版本中的改动。需要合并内容时先在表单中手工修改，再重新读取对照。

采用基准不是保存。原保存同意会被清除，必须重新明确同意后才能走已有版本检查更新。成功保存回到 candidate，启用仍需单独确认。数据库在对照后再次变化，旧基准保存仍被拒绝；对照不是锁或持续更新订阅，也不自动重新读取版本并覆盖。

## 取消、权限与未确认提交

修改表单、切换视图、刷新、取消编辑、取消对照或锁定管理台都会清除对照。未完成请求被取消等待；请求、哈希校验及最终采用前后均检查会话、来源、编辑对象、版本、草稿和视图。迟到结果不能恢复旧对照。清除对照不会替换编辑草稿；明确取消编辑和锁定仍沿用原来的清除行为。

共享给当前身份的他人记录以及导入文档片段没有普通对照采用权限。数据库不存在或已不可见时，读取失败，不能借此获取新保存基准。已归档的自有普通记忆仍能查看对照，但会明确显示 archived；之后明确保存回到候选，不是自动重新启用。相同版本可对照但不能当作新基准采用；退回的版本或同版可编辑字段不一致会被拒绝。

此前提交的交付结果未知时，保留 pending 原事件，并禁止用对照绕过。必须先处理原请求，不能因为读到了某个版本就断言旧写入未成功，或自动生成新事件重复提交。

所有对照数据只在页面内存中，不写浏览器存储、不自动导出。关闭或刷新可能丢失未保存草稿，当前页导出也不包含这份独立对照；不是持久化 outbox 或完整备份。内容哈希校验只验证完整性，不证明记忆真实。管理台仍代表本机 Linux 所有者，不代表其他远端 MCP 身份。

验证归属见 `docs/reviews/memory-comparison/README.md` 和 PR #20 对最终提交的验证记录；受控测试不等于真实 Agent 模型效果或用户主机部署。
