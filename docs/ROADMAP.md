# Ultrabrain 产品开发与验收计划

架构保留：锁定 GBrain 业务引擎、本机托管 PostgreSQL、Ultrabrain 产品层。客户端 outbox 与延后队列是交付日志，不是第二套事实或向量库。OpenViking 按功能吸收，版本指针不代表全功能融合。

## 已落地的阶段增量

0.3.0：持久化 outbox、项目 CAS/历史/续接、主机执行回执、项目遗忘与合成检索评测。0.3.1：队列序列化边界、损坏隔离、136 操作接口合同、迁移账本、真实旧应用升级演练、独立上游检查、安装来源证明与草稿候选 PR。

0.4.0：可选 code_revision 绑定任务和前后 Git 工作区观测，新增只读执行回执查询；可选延后采集，在同一 PostgreSQL 事务持久化原始事件后由同主体当前权限整理；新增普通 MCP worker，默认单批，显式循环。代码绑定不是密封构建；整理成功状态不是模型准确率证明。是否通过仅看具体提交 CI。

## P0 后续：接入与执行恢复

- n8n、通用 HTTP/MCP 及选定 Agent 框架的安装式适配器；稳定身份绑定与可信换凭据流程。
- 输入、工具执行、生成与交付的独立事件；对接执行框架的 checkpoint/interrupt/resume。
- 多主体服务端调度需要新的明确授权模型，不能将队列任务提升为主机权限；增加管理端保留期、重试核查与安全处置。
- 在现有 Git 两时点观测之上增加构建产物、可信 CI 和部署见证，不把旧回执当任意新版本认证。
- 对 GBrain 的 remember、纠正/撤回、时间、技能、图谱逐项产品验收，优先复用上游。

## P1：语义检索与治理

- 0.5.0 已实现可配置的单页全文摘要、原文引用、视图/profile/TTL 失效；后续完成跨文档目录摘要树与真实模型质量验收。
- 0.5.0 增加目录前置补查、查询片段与原文引用展开；后续补齐项目/时间/实体查询规划、多轮递归检索与低置信度策略。
- 针对具体模型 tokenizer 的总上下文预算，不用字节冒充 token。
- 经同意的长会话标注语料；检索与最终答案分别评测，更正、时序、弃答、续接、延迟和成本都要覆盖。
- 更细粒度个人、Agent、项目和团队授权，以及事实版本冲突、来源优先级、有效期和人工纠错。
- 记忆投毒、恶意指令与权限泄露专项评测，untrusted 标记不是完整防护证明。

## P2：生命周期与多模态

- 查询/纠正/导出界面、敏感数据策略、保留期、删除传播及历史备份到期机制。
- 附件与数据库协调备份、静态加密/密钥管理和完整恢复演练。
- 图片、PDF、音视频、代码原始定位，保留页码、时间戳和文件版本。
- OpenViking 无损迁移器与公共接口/资源类型映射，不能仅搬文本就称迁移完整。
- PostgreSQL 跨主版本迁移、pgvector SQL 扩展迁移、验证发行二进制与明确恢复路径。

## 发布门槛

同一提交必须通过单元、运维、真实 PostgreSQL、stdio/HTTP、权限/并发/证据、旧数据迁移、备份恢复与停启检查。0.4.0 验收矩阵从 0.3.0 和 0.3.1 两个不可变基线开始。测试值/受控提取结果不能冒充真实模型质量。全功能等价、用户服务器部署和某个阶段的完成是三件不同的事。

0.5.0 增量另修复实际 native config 路径，既有向量模型身份按数据库记录保留；增加通用 JSON/stdin MCP 客户端与三基线升级矩阵。摘要流程只认证结构和原文引用，不认证语义正确率或事实完备性。

## 0.6.0 阶段增量

已实现资源级当前/历史策略、审核 CAS、有效期、撤回/替代、原生修改失效、有界授权替代跟随，以及基于服务端身份的生命周期事件桥。该层不建立第二套事实库，不能代替 native fact withdrawal 或独立真值判断。

后续优先级：把原生事实更正/撤回与资源证据统一展示；真实客户端 Hook 安装与验证；更细授权及删除传播；模型/token/长会话质量基准。部署默认继续使用托管本地数据库。可选外部 PostgreSQL/多客户端集成需求需作为独立显式模式验收，不通过本次元数据扩展静默改变数据库绑定。

## 0.6.1 阶段增量

已追加资源引用依赖的失效传播和时钟有效性检查，以及 pgvector SQL 扩展显式升级/备份/中断恢复流程。旧版 source_quote 保守标记重审；不改写既有迁移和原生 facts。SQL 路径验收与跨二进制 ABI/数据库跨主版本迁移区分，后者仍需独立演练。

后续重点仍为原生 facts 与资源治理的一致性、具体 Agent/n8n 安装适配及真实长会话效果验证；不把工具接口通过等同于这些工作完成。

## 0.7.0 阶段增量

已加入 native fact ID 与来源版本指纹关联、改动失效、原生生命周期复核和 current/reviewed/history 事实选择；以原生 remember/forget/recall 为底层，不另建事实库。同步/延后提取能对满足严格来源条件的结果登记关联，旧关联与去重其他来源不自动覆盖。Agent 和通用桥提供显式组合召回。

仍待验收：完整原生事实消费入口统一策略、人工/批量历史来源迁移、多证据事实表达、真实模型效果、原生 Agent/n8n 安装适配、多模态与附件恢复。
