# 记忆引用来源核对

本模块接通“记忆／召回结果 → 当前记录 → 直接引用来源 → 版本与引文核对 → 返回原有纠错入口”。它不是新的整理器、递归知识图谱或模型真实性评测，不调用模型，不写入记忆。

## 使用流程

在管理台点击“核对记忆引用来源”。先通过“按 ID 核对”读取一条记录时，该 ID 会自动填入；也可以输入完整小写 UUID。打开或输入本身不查询服务器。勾选读取同意，点击“读取并核对来源”才开始：读取选中记忆，有合法结构化引用时读取它的直接原文，再重新读取选中记忆，拒绝两次之间的内容、版本、可见性、项目、来源说明或派生有效性变化。

来源核对只发送 ID，不发送编辑草稿、用户文件或新的采集内容。服务端仍独立认证每次 `memory_read`；ID不是权限。无引用时只读一次，有引用时最多三次只读请求，不自动重试。根记录和原文都复用既有 `verifyLookup` 完整记录及内容哈希校验，再核对引用合同。核验失败整体清除结果，不用旧缓存补造原文。

页面分别显示本次记忆、生成时记录的引文、原任务 ID、预期及观察版本、SHA-256及匹配标志。来源全文不会默认展示，明确点击“显示本次读取的原文”才显示已读取的全文。显示全文不是新服务器读取；它明确标记为本次观察，不持续刷新。文本用 `textContent`，不执行内容里的 HTML 或脚本。

“打开当前记忆核对／纠错”和“打开当前原文记录”都会重新通过现有精确读取入口查询，不直接编辑缓存。只有之后明确点击编辑、同意保存并通过版本检查，才能修改。原有候选启用仍单独确认；核对不会自动激活、重建派生引用或覆盖草稿。

## 结果含义

- 匹配：本次来源版本、内容指纹、指定 UTF-16 区间引文和返回的派生有效性标志匹配。不证明陈述真实或模型理解正确。
- 来源变化／归档：历史引用保留；即使原文仍含相同句子，也不能当作原版本仍有效。归档不意味着原文物理删除。
- 引文不匹配／观察不一致：明确显示未通过，不把“在别处找到同一句话”冒充指定区间匹配，也不覆盖服务端失效标志。
- 来源不可见／无结构化引用：`not_found`不区分不存在与无权限；网络错误不被归为“不存在”。拥有的无引用记录与他人共享记录的来源字段被隐去分开描述，不由空字段推断从未有来源。

这是三个分别读取时刻的观察，不是同一数据库事务中的原子快照或实时状态保证。重新读取选中记忆可以发现该记录的并发变化，但不能保证来源在读取后永远不变。需要最新状态请明确重新核对。展示来源和引文不构成密码学身份认证、陈述真实性或模型质量证明。

## 引用合同及范围

直接引用复用 `personal-consolidation.mjs` 的既有字段：`job_id/input_id/input_revision/input_hash/profile_hash/quote/start/end/offset_unit`。任务与来源为完整 UUID，来源不能指向当前记录自身；版本在现有范围内。引文为1–2048 UTF-8字节非空、完整Unicode、无NUL文本，偏移单位严格为 UTF-16 code units，结束位置不超过原32 KiB采集输入的最大字符范围，跨度必须等于引文长度。错误引用先拒绝，不能产生下一跳查询。来源读取还须确认为当前拥有的预期记录，不把可见的其他所有者共享记录充当自己原文。

文档整理候选的直接来源可以是已经保存的文档片段，本模块核对该片段；不自动读取整份原始文件，也不把 UTF-16 引用位置冒充 UTF-8 文件字节区间。没有结构化引用的文档片段不推测其父文件。来源本身有引用时也不继续递归。任务 ID 和模型 profile hash 仅展示原有来源信息，不读取模型配置、凭据或任务正文。

纯函数 `lineageReference`、`compareLineage` 和 `sameLineageRecord` 接受已经由现有精确读取验证器核验的记录；它们不是独立网络认证器或未经验证记录的哈希校验替代品。原数据库、MCP工具列表、权限、迁移、依赖及上游锁不变，仅新增两条固定静态代码路径。

## 撤回与数据边界

修改 ID 撤回当前同意并清空结果；取消、导航、刷新、锁定、写入或打开快照工作区也会清除来源数据。每次请求前后、异步指纹计算后及后续显示／跳转动作均检查会话、来源、导航、选择、同意、busy/pending和面板状态；过时错误不能覆盖新结果。已发送的只读查询不能撤回，不承诺内存安全擦除。未确认写入阻止启动本模块，不能借此绕过原事件恢复。

不下载、不写浏览器持久存储、不操作剪贴板、不读取其他会话或用户附件。索引、正文、引用和ID均可能包含私有信息，页面不自动脱敏；不防御恶意同账号脚本或被控制的浏览器。独立编辑草稿和原未确认请求不被接管。

## 验证

两个新 Node 测试套件覆盖纯引用规则、实际浏览器脚本配合合成DOM/HTTP、撤回竞态及既有CI覆盖保留；HTTP单测核对新固定静态路径。`test/personal-lineage-integration.mjs` 使用一次性PostgreSQL、真实原生MCP dispatch和实际Chromium，准备阶段明确写入四组整理来源（含真实文档片段）并注入四次合成生成器调用，不调用外部模型。

浏览器只读阶段要求六张表指纹一致、无下载，Python独立计算引文区间和SHA-256；另起浏览器阶段在真实来源读取后明确修改选中记忆，要求旧来源结果拒绝，数据库仅增加一次明确事件并修改目标记录，其余来源、记录和任务不变。两阶段不能合称全程只读。最终提交的CI和独立审核结论以PR #20的具体记录为准，不代替用户主机或整套个人V1发布验收。
