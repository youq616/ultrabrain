# 从召回结果核对当前记录并纠错

管理台增加「按 ID 核对」，召回卡片增加只读按钮「核对最新记录」。输入完整小写 UUID 或点击该按钮，都会重新读取当前身份可见的单条记录，不把旧召回卡片直接变成编辑依据。打开视图、修改 ID 或普通刷新不会自动读取。

## 三个入口，一个 Store 合同

`PersonalMemoryStore.read({memory_id})` 是唯一读取实现；兼容 MCP 新增只读工具 `ultra_memory_read`，管理台映射为 `memory_read`，已安装客户端的只读工具列表也允许转发。只接收 memory_id，不接收调用方指定的 source_id、actor_key、状态或 SQL。认证主体及来源沿用服务端推导。新工具不改变 governed 工具白名单，不是新增管理员接口。

所有者可核对自己的 active、candidate、archived 条目，包括来源已经失效的派生记忆。其他主体只有当前 active、明确 source 共享且派生来源仍有效的记录可见，私有来源引用不对其暴露。跨来源、不存在、不可见的 ID 统一返回 not_found，不分别泄露存在性原因。UUID 是选择条件，不是授权凭据；项目标签不把其他已有工具的授权语义改为新的项目 ACL。

参数化查询在只读事务中执行，使用事务内5秒 statement_timeout 和 LIMIT 1。返回完整记录（内容、版本、状态、可见性及原有投影字段）或错误；序列化结果超过1 MiB整体拒绝，不裁切文本。该限额约束返回值，不是对数据库内核分配的硬实时保证。数据库故障不伪装成 not_found 或成功空结果。

## 明确核对，再明确编辑

结果显示本次读取的版本和状态，可能已经从 active 变回 candidate，也可能已经归档。点击「编辑」才把这一次读取的版本填入原有表单，并清除保存同意。核对和切换 ID 不覆盖右侧未保存草稿；取消核对只清除结果，不清除另行编辑的草稿，取消编辑仍使用原按钮。

保存沿用 expected_revision 检查：读取后仍可能有并发修改，旧版本会被拒绝，不能自动重读一个新版本然后覆盖。编辑后的内容回到候选，激活仍需明确确认。共享记录和导入文件片段不展示普通编辑/审核按钮；导入片段生命周期继续走文档入口。读取不新增事件、记忆或模型任务，后续明确的保存/审核才是写入。

每次读取冻结 ID、会话、来源及当前视图，fetch 和内容 SHA-256 验证之后都复核。修改 ID、取消、导航、刷新或锁定后，迟到结果不能重新填充页面；完成结果也可直接本地清除。哈希验证只校验完整性，不证明记忆真实。已发送查询不能撤回，页面没有自动重试，也不是持续数据库变更订阅。

当前页导出仅包含已核对的单条结果，不是完整备份或历史快照。令牌不写浏览器存储或 URL，锁定清除查找 ID。此管理台代表本机所有者，不等于远端其他身份收到的上下文。

## 验证边界

专用 Store/浏览器 JS 单测与真实集成分别记录。真实集成覆盖原生 MCP dispatch、实际 stdio 与双 HTTP 凭据、npm 安装后的客户端代理，以及 Chromium 的“旧召回后并发改变→精确读取新版本→编辑→候选→确认→旧版本保存拒绝”。

浏览器夹具先执行只读阶段并比较5张表，再单独执行明确的合成纠错写入；后一个阶段不能称为数据库未写入。所有夹具数据均为合成内容，不是用户主机部署、实际 Agent 模型运行或模型质量验收。精确提交的执行和独立审查结果以 PR #20 最新验证记录为准。
