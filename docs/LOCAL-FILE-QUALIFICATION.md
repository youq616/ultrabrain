# 本机文件读取兼容核验与 Windows 零路径设备号

本模块基于 PR48 `262b2138bedc423b2a6886dcade9f998e421d66d`，不修改服务器、记忆权限、队列锁协议、上游依赖或其他项目。

## 实际定位与修复

本轮先以 staging commit `d2367c8db075bece21be576780086cfca9267401` 在真实 Windows2025 / Node22.16.0 / libuv1.49.2 上运行未修改的生产读取器。工件11070587674（run36651409117）明确观察到 path_device_zero=true、handle_device_zero=false，只有dev不同，inode及其他字段相同。两种读取策略均在handle-before/identity拒绝。不是从“两个unsigned32不同”猜测零值，也没有输出原始设备号或inode。

修复仅允许 **Windows路径侧设备号为0，但两个独立打开且全程持有的句柄均有相同非零设备号** 的情况进入既有双句柄核验。数值兼容助手仍拒绝0与非零互相匹配；没有把0当通配符。两个句柄的设备、inode、类型、模式、链接数、UID/GID、大小和纳秒时间必须在前后全宽一致，路径前中后样本也必须一致。非Windows不放行；句柄设备号缺失不能为不同的路径设备号提供身份依据。文件变化、权限错误和别名政策不变，EPERM不重试。

这更新了旧 `LOCAL-FILE-DESCRIPTOR-ANCHOR.md` 的“两边必须非零”前提：路径侧允许缺失，实际设备身份仍由两个非零句柄确认。旧文档中的原始实验及限制继续保留。可信本地目录前提不变；这不是恶意同用户沙箱、卷/ACL认证、原子快照或全文件系统兼容声明。

## 独立离线命令

使用本提交构建的私有客户端包后运行：

```sh
ultrabrain-local-check
ultrabrain-local-check --help
```

源码入口为 `node scripts/check-native-file-qualification.mjs`。不接受profile、文件路径、队列或服务器参数，不读取stdin。它只在操作系统临时目录内创建一个全新合成文件，分别使用生产profile与outbox读取策略校验，并删除自己的临时目录。它不是只读程序：有明确的合成文件写入，但不选择用户文件、不写记忆、不联网、不导入MCP SDK、不启动服务器或模型。

SDK：`require('ultrabrain-client/dist/local-check.cjs').qualifyLocalFileRuntime({signal})`。signal可省略；导入SDK不执行IO。参数只允许自身数据属性，不默默忽略继承的取消设置。取消在同步IO边界检查，不承诺中断阻塞系统调用；已创建的临时数据仍执行清理。原始异常中的getter、路径、消息、设备标识不用于输出。

报告保留设备关系、零值标志和不同字段的名称，以及现有安全读取诊断。任何读取、元数据观察或清理失败都不返回passed=true。两个策略分别报告，不把第二种策略的检查当作对同一次失败的自动重试。清理错误与原错误分开保留，观察句柄只尝试关闭一次。

**通过只说明临时目录所在文件系统的这次合成读取成功。** 不证明另一块磁盘上的真实队列可用，不认证ACL，不证明多进程并发或网络连接，没有永久缓存或自动升级。失败也不授权删除旧锁、改权限、搬迁队列或禁用身份检查。

## 验证与证据

两项零路径设备号消费者回归在旧读取器上0/2通过；修正后通过。新增测试69项（22条零设备关系、39条核验/CLI、8条实施者审计）。旧参数化测试中“路径为0必须拒绝”的一项由新行为覆盖；缺失句柄及无效范围的拒绝断言保留。相对基线测试数净增68。

本地普通UID1000 / Linux / Node22.16.0全量4030/4030通过，零失败/跳过/取消。Win32统计替身不算原生Windows证据。最终私有包实际解包：13个编译产物散列核对，离线CLI/SDK9项通过（禁止MCP/网络模块导入）。原生产客户端读取与并发队列检查另行记录，不能把单文件通过等同EPERM已修复。

实施者单独审计发现继承options及descriptor原型可能影响取消选择，已改为精确自身属性并使用无原型文件选项。首次审计8项6过2败留档。一条测试最初要求全Node内部在被污染的全局原型下继续成功，超出本模块承诺；修正夹具为在首个受控IO边界验证未继承取消，不隐去真正参数边界断言。首次39项中1项错误注入命中了准备写文件的内部close，已限定观察句柄后通过。它们不是远程JSON漏洞或真人独立审核证明。

实际原生结果按最终提交更新到PR；staging结果不代替最终SHA。独立第二代理审核也单独记录，不用自查或旧提交反馈冒充。
