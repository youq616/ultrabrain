# 0.6.0：资源级记忆更正与有效期

此层为原生页面添加选择策略，不复制正文、事实库或向量库。它适用于项目决策、说明文档和资源版本；**不是原子事实的完整时态推理系统**。`active` 表示有人对当前页面版本作过明确审核，不代表陈述已被独立证明。

## 当前知识与历史资料分开

`ultra_read`、`ultra_retrieve`、`ultra_ls`、`ultra_excerpt` 新增 `memory_policy`：

- `current`（默认）：保留未审核资源以兼容已有资料；排除撤回、被替代、失效、尚未生效和原文变化后待重审的资源。
- `reviewed`：只使用已明确审核且在有效期内的当前版本。被标为 inference 的审核资料仍是推断，不自动成为事实。
- `history`：显式查阅历史原文，响应携带状态标记；不绕过原生 source、可见性、目录或客户端权限。

未审核资源返回 `unreviewed/unclassified`，不能说成“全部已验证”。结果继续受原生候选上限及扫描窗口影响。过滤发生在已有候选内，补足结果并不等于穷尽检索。

每条返回证据带 `memory` 状态。普通模式不会以旧全文代替当前结论；旧出处需要显式 history 才能展开。语义摘要生成也检查当前策略，撤回或审核变更会清理该页面的派生摘要，包括正在生成的租约记录；不会偷偷为已撤回页面调用摘要模型。

## 审核与撤回

先调用 `ultra_memory_inspect` 读取页面当前 `content_sha256` 和 `memory.revision`，再提交：

```json
{
  "uri": "ultra://development/decisions/database",
  "event_id": "review-0001",
  "expected_revision": 0,
  "content_sha256": "这里填写实际返回的完整SHA256，不能使用此占位符",
  "status": "active",
  "assertion_kind": "attributed",
  "reason": "确认采用目前文档中的方案",
  "provenance": "本次项目决策记录"
}
```

工具为 `ultra_memory_review`。`status` 可为 active 或 retracted；首次审核版本为 0，其后必须使用最近读取的 revision。两个写入者使用同一版本时只能有一个成功。event_id 相同但内容或主体不同会拒绝；原文已经变化时须重新读取，不可把重试当成对新版本的授权。

`assertion_kind` 必须选择：attributed（带归属的陈述）、inference（明确推断）或 source_quote。source_quote 还要求 evidence 对象 `{uri, content_sha256, start, end}`；系统核对同源、当前可读原文的精确引用区间。保存的只是引用位置与 hash，不复制引用正文。**找到原句不证明陈述为真，也不证明原句蕴含整篇资源的结论。**

撤回的页面仍保留原文。重新启用 retracted 或 superseded 资源需要额外明确 `reactivate:true`，不是通过导入旧文本自动复活。没有永久物理擦除的承诺。

## 替代旧决策

先创建并审核新页面，再调用 `ultra_memory_supersede`：旧 URI、旧内容 hash、旧政策 revision、replacement_uri、replacement_sha256、replacement_revision、event_id、reason、provenance 均必填。

新旧页面必须属于同一授权 source。新页面必须已有 active 审核且当前有效。服务器按确定顺序锁住原生页面，检查版本，再在同一事务中写入旧页面的 superseded 状态和审核历史；不会重写两个正文。

检索命中旧资源时，可沿明确的替代关系找到新资源。每一跳都检查原生权限、请求目录边界和替代内容 hash，最多 4 跳、一次检索最多 16 次替代尝试；不执行正文中的跳转指令。结果标记 `redirected_from`，原排名来自旧命中而不是伪造新页面搜索分数。

新目标内容修改后，旧替代边的 hash 失效，不会默默跟随任意新正文。需要重新审核并显式更新替代关系。目标不可读、已撤回、已删除或超出范围时，不泄露其 URI 或正文。直接读取旧 URI 不自动换页；调用者选择 history 或查阅修订记录。

## 时间、原文变化与历史

valid_from 与 valid_until 使用严格 UTC ISO 时间（例如 `2026-09-12T02:00:00Z`），起点包含、终点不包含。省略或 null 表示无该边界。服务器按数据库当前时钟判断，不使用客户端提交的“现在”。这是页面有效期选择，不是对任意历史时间的完整状态重建。

原生正文、标题、frontmatter、路径或删除状态变化触发 review_required，并追加版本；已撤回/被替代状态继续保留。读取还对授权视图的 canonical hash 复核，以防标签或隐私视图变化。物理删除后同 source/slug 的重新导入仍受旧策略限制；重新命名为不同 URI、删除整个 source、恢复旧备份或在别处复制资料需要独立的数据生命周期策略。

`ultra_memory_history` 返回审核历史。远程读者可以看到状态版本，但其他主体的自由文本审核理由与引用细节不会随 source 读权直接泄露；主机与该条审核的同主体可查看自己的详情。历史工具必须先通过当前原生页面读取授权，已经不可读/不存在的页面不通过此接口暴露审核数据。

## 权限和范围

审核与历史工具当前需要完整 source grant，不对目录受限、delegated 或退化授权开放。当前/历史筛选仍适用于通过原生 ACL 的受限读取。事件字符串不能覆盖源身份。

**直接使用 GBrain 原生 `get_page/search/recall` 等入口，不会自动套用这个资源策略。**它们保留原有接口语义；原子事实撤回继续使用原生事实工具。仅在资源策略下撤回文档，不会撤回从中提取的全部事实，也不删除散落在其他文档中的相同文字。使用 AgentMemory 或事件桥可走默认 current 路径，但不能据此宣称所有客户端都已避免旧事实。

实现参考 PostgreSQL 官方行锁与事务机制：https://www.postgresql.org/docs/18/explicit-locking.html 。源读取、策略和生成回答不是一个全局事务；返回反映检查时的状态，不能保证任何并发后续改动都已经包含。

## 0.6.1：引用依赖的失效传播

source_quote 审核现在登记当前引用来源与 SHA-256；正文仍只有原生页面一份，依赖表不复制原文。引用的是另一个资源时，该来源必须在当前有效范围内，且其政策版本在审核提交时没有改变。

原文变动、删除、恢复、重命名，或显式撤回/替代，会使依赖该来源的 active 审核转为 review_required，追加历史，并由现有触发器清除派生摘要。传播覆盖多层依赖；循环引用通过去重集合终止，不因同一轮传播反复增加版本。改用新的引用源会替换当前依赖边，旧边继续只存在于历史快照中。

仅因时间流逝而过期的来源不会触发 SQL UPDATE，因此读取还按数据库当前时钟检查依赖链的生效/过期状态。来源不再有效时依赖资源不进入 current/reviewed 结果。它不是对任意历史时间重建全部事实，也不证明引用蕴含结论。

迁移 0007 对旧版仍 active 的 source_quote 标记待重审。旧版未保存可直接使用的依赖索引，本版不通过猜测解码 URI 补造更强的保障；原文和旧审核记录保持不变。重新审核后才登记依赖。attributed 和 inference 不受这项一次性迁移影响。

引用更正仍是**资源级选择规则**，不能自动撤回已经被提取到原生 facts 的所有事实，也不能在回答生成后追溯取消已返回的内容。source_quote 的精确区间验证与语义/真实性审查仍是两项不同的工作。
